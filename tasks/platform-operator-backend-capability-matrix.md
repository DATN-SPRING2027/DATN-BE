# Platform Operator Backend Capability Matrix

**Branch:** `feat/Thang-platform-operator-v1-be-api`
**Contract:** [`iam-v1.openapi.json`](../docs/openapi/iam-v1.openapi.json)
**Baseline:** [`platform-backend-api-capability-audit.md`](../docs/platform-backend-api-capability-audit.md) is immutable historical input; this matrix is its V2 implementation successor.

This matrix reports backend capability and FE consumption separately. Status
cells use only `IMPLEMENTED` or `BLOCKED_EXTERNAL_DEPENDENCY`. A backend status
of `IMPLEMENTED` does not imply that the existing FE page calls that route.
Every Platform endpoint uses the authenticated Platform principal, server-side
permission resolution at `PLATFORM` scope, and safe projections. Mutations use
CSRF for cookie sessions and enforce their documented version/idempotency
preconditions where applicable.

## Scope decisions and remaining gates

- Organization lifecycle is conditional in the request. The current Organization
  model has no lifecycle status/state machine, and DEC-ACCESS-09 does not approve
  one. This matrix therefore does not invent suspend/reactivate transitions.
- Platform invitation commands retain their existing no-write 503 gate until the
  A7 notification-provider evidence and A8 coordinated cutover are approved.
  Membership remove/restore/role change are not exposed as Platform routes
  because the required reviewed state-machine and cutover contract is not
  approved. They remain an explicit backend contract gap: no success API is
  claimed and Organization Admin routes are not presented as Platform routes.
- Organization lifecycle is conditional in the request. The current model has
  no lifecycle status/state machine and DEC-ACCESS-09 does not approve one, so
  no lifecycle route or status transition is invented.
- Jira test/reconnect endpoints now have runtime/API contracts, strict input
  checks, a signed bounded internal adapter, safe failure mapping and tests. The
  production provider remains unavailable until Jira owns credential decryption
  and provider-client/test/reconnect behavior.
- SAG does not expose model-provider health or safe processing job/failure data.
  The backend reports unsupported fields explicitly as `NOT_EXPOSED`; it does
  not modify SAG ingestion or indexing.
- Incident storage, request-trace indexes, session-fence fields and V2
  authority schema validation are in the separate
  `feat/Thang-platform-operator-incidents-db` worktree. They are additive, have
  deterministic planner/schema tests, and have not been applied to a live
  MongoDB.
- FE repository `DATN_FE` was inspected read-only. Its routes share a console
  component; it currently calls only platform session/login/logout, organization
  list/detail/create, exact email lookup, organization membership list/suspend,
  IAM health, and the legacy capped audit feed. V2 users, session, project,
  service directory, job, AI, integration, incident, diagnostics and advanced
  audit routes are not yet wired into FE hooks/pages.
